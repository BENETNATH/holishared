## Points confirmés

- **Migration** : `plan_identity_migration` et `migrate_identity` partagent `_run_identity_steps(apply=…)`. Le calcul à blanc n'écrit rien, et la projection des participants prévus (`planned`) rend les compteurs identiques dans les deux modes. Chaque étape est conditionnée par la valeur héritée, donc une 2e exécution renvoie des zéros, sans sauvegarde (M23/M24 verts). Base vide : plan à zéro, aucune sauvegarde. Un seul commit, rollback puis propagation en cas d'erreur. La sauvegarde précède l'écriture : si elle échoue, rien n'est migré. Démarrage : sous le `try/except` journalisé, comme le veut la spec §4.1. Exécution unique par processus (`create_app`), donc pas de course entre threads Waitress. URI SQLite absolue résolue avant la sauvegarde. `sqlite3.backup` est compatible WAL et réessaie sur une base verrouillée. Rotation : 3 fichiers au plus, rien au-delà de 30 jours, aussi appelée par la purge. `check` force `SKIP_STARTUP_MIGRATION`.
- **Limiteur** : `IP_FAILURES` et `EVENT_TARGET_FAILURES` en `shared_limit` + `deduct_when` (POST seulement). L'alerte par cible ne renvoie jamais de 429. Repli mémoire activé (`in_memory_fallback_enabled`, `swallow_errors`) et appel direct protégé par `try/except`. Codes normalisés (`strip().lower()`) sur `access`, `mycode` et `join`. Réponses identiques pour un format invalide et un code inconnu. Le code saisi n'est jamais journalisé. `X-Forwarded-For` : nginx utilise `$proxy_add_x_forwarded_for` et `ProxyFix(x_for=1)` prend le dernier saut ; le port 8400 n'est qu'`expose` → pas d'usurpation d'IP par l'en-tête. La comparaison n'est pas à temps constant, mais la recherche passe de toute façon par l'index SQL : sans effet pratique. Plafond assumé : la vérification avant décompte laisse passer une rafale concurrente (4 threads, burst nginx 20) au-delà du quota, puis bloque.
- **D19 / IDOR** : toutes les routes des 9 blueprints chargent le contexte avant l'objet. Chaque recherche par `id` est filtrée par `event_id` (ou `list_id` / `poll_id` de l'objet parent déjà filtré), y compris les `household_id` de formulaire (`_household_in_event`), `meal_id` (`move`) et `option_id`. 403 et 404 sont rendus par gabarit (gestionnaires globaux) ; plus de chaînes « Not found » / « Pas autorisé. » dans costs, media ni meals.
- **verify** : code existant conservé (champ vide ou identique), nouveau code de 8 caractères exigé, unicité vérifiée hors du créateur courant ; `IntegrityError` → rollback, nouveau rendu, événement non vérifié ; jeton à usage unique. Sessions Flask signées côté client : pas de fixation possible.
- **ensure_creator_guest** : flush sans commit ; seul appelant hors contexte, `verify`, commit dans la vue. `get_or_create_creator_participant` commit le repli (sauf la branche du constat 6).
- **Droits** : participant créateur non supprimable (`_allowed` index 1 sur `Guest`) ; suppression du contenu d'autrui refusée (chat, media, planning, meals) ; `members` POST d'un invité ignoré ; codes d'autrui affichés au créateur seulement (`members.html:49-52`), code personnel affiché uniquement à son titulaire (`dashboard.html:27`).
- **B017** : `/_ui` → 404 sauf `UI_CATALOG_ENABLED=true` (désactivé par défaut). `/sw.js` en `no-cache` avec `Service-Worker-Allowed: /` ; le service worker ne met en cache que les `/static/…?v=` versionnés et la page `/offline`, pas les pages authentifiées : les navigations passent par le réseau, avec repli hors ligne. `/offline` ne rend aucune donnée de session. CSRF : CSRFProtect global, jeton présent dans les formulaires déplacés. `inject_globals` ne fait aucune requête et n'expose que le contexte déjà chargé.

- Verdict : **APPROUVÉ SOUS RÉSERVES**. 0 bloquant, 3 majeurs, 4 mineurs.
